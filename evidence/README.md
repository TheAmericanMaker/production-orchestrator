# Executed Spike Evidence

These reports were generated by real Strands 1.51.0 executions against the synthetic shop fixture.

- [`bedrock-rejection.json`](bedrock-rejection.json): Amazon Bedrock/Nova Lite interrupt resumed with rejection; domain state stayed at revision 1.
- [`bedrock-approval.json`](bedrock-approval.json): independent Amazon Bedrock/Nova Lite interrupt resumed with approval; the exact proposal advanced state to revision 2.
- [`bedrock-verdict.json`](bedrock-verdict.json): hashes both independent reports and records the paired gate as `VALIDATED`.
- [`bedrock-restart-rejection.json`](bedrock-restart-rejection.json): process A persisted a real Bedrock interrupt; process B restored it and rejected without mutation.
- [`bedrock-restart-approval.json`](bedrock-restart-approval.json): an independent process pair restored the interrupt and applied the exact approved proposal once.
- [`ollama-workflow-rejection.json`](ollama-workflow-rejection.json): live local `gemma4:e4b` intake workflow restored in a fresh process and rejected without mutation.
- [`ollama-workflow-approval.json`](ollama-workflow-approval.json): independent live local `gemma4:e4b` run restored and applied the exact approved proposal once.
- [`ollama-workflow-performance.json`](ollama-workflow-performance.json): machine-readable local hardware/model details, token counts, latency measurements, methodology, and report hashes.
- [`OLLAMA_WORKFLOW_RUNS.md`](OLLAMA_WORKFLOW_RUNS.md): human-readable account of the local runs, correctness results, performance comparison, and benchmark limitations.
- [`rejection.json`](rejection.json) and [`approval.json`](approval.json): earlier Ollama fallback development evidence retained for comparison.

Each report includes:

- Provider/model and SDK version
- Interrupt ID, name, proposal hash, and reviewed changes
- Pre-interrupt and final domain digests
- Final schedule and procurement tasks
- `AgentResult` tool metrics
- Persistent application audit events
- Eight machine-evaluated workflow checks
- Honest submission-gate status

Each individual Bedrock report deliberately remains `PARTIAL` because one path cannot prove the paired gate. `provider_path_passed: true` means that path passed. The aggregate `bedrock-verdict.json` is the only artifact that claims `submission_gate_passed: true`, after verifying both independent reports.

The Bedrock evidence uses the named least-privilege `production-orchestrator-bedrock` profile, `us-east-1`, and `amazon.nova-lite-v1:0`. No credential values or credential-file contents are recorded.

Runtime databases and `FileSessionManager` artifacts are intentionally ignored because they contain transient conversation state. Their existence and file counts are captured by the evidence checks.

The restart reports are intentionally narrower than the original paired workflow reports. They record provider/model/region, distinct process IDs, the restored interrupt ID, exact proposal hash, final revision, audit event types, and application count. They prove fresh-process session reconstruction; the original `bedrock-*` workflow reports remain the evidence for all seven shop tools and the paired submission feasibility gate.

The August 13 local Ollama reports use `gemma4:e4b` through Ollama 0.32.9. Unlike the narrower Bedrock restart reports, the local `ollama-workflow` path begins with customer intake and therefore exercises eight tools. Both local decisions passed, but they remain development evidence for provider independence; Amazon Bedrock remains the judged provider.
